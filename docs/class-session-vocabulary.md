# Синхронизация Vocabulary

В живом классе доступны `warm-up`, `lead-in` и `target-vocabulary`.
Черновик и оба участника используют существующий `LessonView` и одни и те же
компоненты. CSS компонентов не изменяется для синхронизации.

## Ответственность модулей

- `assets/components/exercise-state.js` — общие чистые правила действий и
  представление упражнения без ключей. В черновике правила вызываются локально,
  в классе — серверным обработчиком. Авторские нормализаторы компонентов остаются
  строгими и не принимают формат сетевого представления как авторский JSON.
- `assets/components/*.js` — существующая разметка, жесты, анимации и отображение.
  Компонент принимает `exerciseState`, `interactive`, `onAction` и, для упражнений
  с ключами, `presentation`. Методы `updateState` и `setInteractive` меняют DOM
  без повторного создания упражнения. Обновление состояния не отправляет действия.
- `assets/class-component-adapters.js` — связывает компонент с сессией. Предварительно
  отображает выбранную фразу, набираемый текст и отметки, но не вычисляет правильность
  ответа на ученическом клиенте.
- `assets/class-session.js` — существующая очередь и WebSocket. Политика конфликтов
  версий и потери неподтверждённых действий при отключении не изменена.
- `lib/class-component-handlers.js` — права, проекция содержимого и вызов общих правил.
- `lib/class-session-store.js` — состояние конкретного класса в `class_live_state`.
  Ответы не изменяют JSON урока. Раскладки `_layouts` создаются и сохраняются также
  для уже существующих классов; новая SQL-миграция не нужна. Они не передаются клиентам.

`LessonView.renderStageContent(stage, true)` согласует состав блоков при показе
или скрытии карточки, сохраняя неизменившиеся узлы на месте. Это сохраняет фокус
и ввод в соседнем упражнении. При удалении компонента вызывается его `dispose`;
Match Words освобождает обработчики перетаскивания и его плавающую карточку.

## Поведение

| Компонент | Действия и права |
| --- | --- |
| `matchWords` | Ученик выбирает фразу кликом или началом перетаскивания (`select-word`). Выделение видно учителю. Отпускание на картинке или клик по ней отправляет `match-word`. Координаты указателя не передаются. |
| `dropdownChoice` | `choose-word` разрешён ученику. Учитель может открывать меню, включая уже решённые пункты; попытка сменить значение возвращает общий ответ без отправки действия. |
| `fillInBlanks` | `type-answer` отправляет текст по мере ввода. Учитель видит его в read-only поле. Совпадение проверяется без учёта регистра и лишних пробелов; правильный ответ остаётся редактируемым. |
| `describeAndGuess` | Изначально скрыт у ученика. Учитель управляет показом через `set-visibility`. Оба участника могут отправлять явное `set-crossed`, ученик — только пока упражнение показано. |
| `personalizedQuestions` | Общее статическое содержимое и устные ответы. |
| `markdownCard` | Существующая политика `always` / `controlled` / `teacherOnly`. |
| `teacherNote` | Не передаётся ученику. |

Match Words использует независимые случайные идентификаторы слов и картинок.
Публичное представление содержит два отдельных списка и `answerKey` со связью
wordId → targetId для локальной проверки. Ключ не отображается в интерфейсе,
но доступен через DevTools. Порядок банка Match Words и Fill in the Blanks фиксируется для класса
и не меняется при переключении стадий или перезапуске сервера. Учитель получает
полное авторское содержимое и то же публичное представление; встроенный Answer Key
Fill in the Blanks строится из авторских ответов только для учителя.

Правильная пара сохраняется в `exercises[componentId].matches`. Компонент завершает
анимацию сразу при локальной проверке, скрывает слово в банке и блокирует картинку.
Очередь действий накладывается на подтверждённое состояние; сервер независимо
проверяет пары. Ошибка синхронизации откатывает неподтверждённые результаты.
Неправильная пара не добавляется: оба экрана показывают существующую подсветку
ошибки, у ученика карточка возвращается в банк. Состояние содержит только последнюю
попытку с номером `sequence` и ID `id`, а не историю.
ID предотвращает повтор анимации ученику при подтверждении; учитель видит результат
после доставки с сервера. Анимация запускается один раз для нового
результата действия; первоначальная отрисовка и snapshot её не проигрывают.

## Проверки

`npm run check` включает тесты общих правил, прав, компонентов с тестовым DOM,
клиентских адаптеров и реальную пару WebSocket-подключений с перезапуском сервера.
Браузерная проверка визуала и жестов остаётся за пользователем.
