# Указатели в живом классе: прототип Reading

Прототип включается автоматически у учителя и ученика на стадии `reading`.
Он поддерживает компоненты `textReading`: заголовок, подзаголовок, основной
текст и загруженные изображения. Квизы, ключи ответов и остальные стадии
пока не размечены. Формат JSON урока не изменён.

## Адресация

Рендерер `assets/components/text-reading.js` создаёт `data-cursor-text`
(`title`, `subtitle`, `body`) и `data-cursor-target` (`headerImage`, `textImage`).
ID компонента берётся из JSON. Позиция текста — смещение UTF-16 в последовательности
текстовых узлов конкретного поля, без тегов. Обе роли получают одинаковый текст
Reading. На принимающей стороне DOM Range находит символ уже в местной вёрстке.
Для браузеров без `caretPositionFromPoint` используется `caretRangeFromPoint`;
если оба API отсутствуют, текстовая цель не отправляется, изображения продолжают
работать. Для расширения на задания с пропусками нужны отдельные стабильные
текстовые сегменты, а не смещение во всём изменяемом абзаце.

Координаты изображения нормализованы относительно исходной картинки; учитываются
`object-fit: contain/cover` и центральная обрезка, используемые Reading. Если
искомая часть картинки у получателя обрезана, указатель скрывается.

## Транспорт и жизненный цикл

`/ws/classes/:id/cursors?role=teacher|student` — отдельный WebSocket с отдельным
обработчиком `lib/class-cursor-signaling.js`. Требуется авторизация класса,
допустимый Origin и активное основное соединение этой роли. Сервер берёт роль
из авторизации, проверяет активную стадию и разрешает только публичные поля
Reading. Состояние урока не записывается, версия не увеличивается, снимки урока
на каждое движение не формируются.

Клиент отправляет не более 20 обновлений/с; неподвижную мышь подтверждает раз
в секунду. Сервер пропускает не более 40 сообщений/с, размер сообщения ограничен
1024 байтами; при очереди более 4 КБ новые промежуточные позиции пропускаются.
Оба WebSocket работают в общем серверном процессе, комнаты находятся в памяти.

Смена стадии и потеря основного соединения закрывают канал указателей.
При отдельном обрыве канала курсоров он переподключается с задержкой 0,5–10 с.
Уход мыши, потеря фокуса и скрытие вкладки сбрасывают локальную цель; уход
собеседника скрывает удалённую. Без подтверждения мышь исчезает через 3,5 с.

Короткое касание показывает кольцо примерно на 1,2 с. Свайп не блокируется и
не превращается в указатель. При цели вне экрана появляется кнопка направления:
прокрутка начинается только по нажатию. Указатель не перехватывает клики и не
рисуется поверх меню, перекрывающего материал.

## Проверка

`npm run check` включает тесты отдельного канала: авторизацию, изоляцию класса,
передачу в обе стороны, допустимые цели, неизменность состояния урока, работу
основного канала при потоке курсоров и очистку при отключении.

Для визуальной проверки открыть один живой класс двумя участниками, выбрать
Reading, установить одному окну ширину 1440 px, другому 390 px и закрыть план,
если он перекрывает мобильный материал. Проверить одно и то же слово при разных
переносах строк, изображения, независимую прокрутку и кнопку перехода, касание
и свайп, смену стадии и переподключение курсора. Прототип проверен в Chrome с
эмуляцией мобильного viewport/touch; Safari и физические устройства требуют
отдельной проверки перед распространением на остальные компоненты.
