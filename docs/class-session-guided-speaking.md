# Синхронизация Guided Speaking

Стадия `guided-speaking` доступна в классе. Учитель переключает стадию через
существующую сессию; ученик следует за ним. Инструкция, How to Play и Speaking
Support доступны обоим. Teacher Note не передаётся ученику. Example Dialogue
использует существующую политику Markdown Card (`always`, `controlled`,
`teacherOnly`); настройки авторского урока сохраняются.

Guided Role Cards использует один рендерер для черновика и обеих ролей класса.
Авторская валидация по-прежнему требует обе роли. Представление `presentation`
проверяется с учётом viewerRole: ученик получает только student, учитель —
student и teacher. Проверка структуры и текстов ролей общая. Сервер формирует
представление для HTTP и WebSocket; карточка учителя отсутствует в данных
ученика. Редактирование доступно в авторском режиме через прежний onSave.

Переворот каждой карточки остаётся локальным в компоненте, не отправляет
действий и не сохраняется в class_live_state. Обновления сессии и восстановление
соединения на той же стадии сохраняют DOM и открытые карточки. После ухода
со стадии или перезагрузки страницы карточки снова закрыты. Новых событий,
таблиц и миграций нет. Разметка, CSS и анимация карточек не изменены.

Автоматические проверки покрывают фильтрацию HTTP/WebSocket, доступность стадии,
восстановление после перезапуска сервера, отклонение попыток сетевого переворота,
валидацию представления, редактор черновика и сохранение локального переворота
при обновлении сессии.

Браузерную проверку выполняет пользователь:

- Открыть Guided Speaking у учителя и ученика, проверить переход по команде учителя.
- Сравнить оформление с черновиком; проверить инструкции, Speaking Support и диалог.
- Проверить две карточки у учителя и одну у ученика; перевороты независимы.
- Проверить сохранение переворота при переподключении на той же стадии.
- Проверить редактирование и сохранение обеих ролей в черновике.
