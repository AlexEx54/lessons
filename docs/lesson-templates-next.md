## 2. Шаг 1: хранение копий и раздел «Шаблоны»

Решения (согласованы 2026-10-14):

- порядок генерации по-прежнему считается топологической сортировкой, движок не
  трогаем;
- системные шаблоны — обычные JSON, компилируются при использовании, как копии;
  проверки при старте сервера нет, сломанный файл ловят тесты;
- шаблон 1 до 0c-2 был виден в списке с пометкой «нельзя копировать»; после
  0c-2 копируются оба, признак `copyable` убран;
- синтетический режим копий собирается из `example()` контролов
  (`createExampleLesson`); системные шаблоны до 0c остаются на рукописных
  синтетических уроках;
- раздел «Шаблоны» — отдельная страница `/lesson-templates` в меню админа рядом
  с «Черновиками»;
- копию можно удалить, даже если по ней есть черновики: они работают по снимку;
- копии общие для всех админов, `created_by` только показывает автора.

### 1a. Сервер ✓

- Миграция `021-lesson-templates.sql`: таблица `lesson_templates` и
  `lesson_drafts.template_snapshot_json`.
- `lib/lesson-template-store.js`: список (системные, затем копии от новых),
  чтение с определением, копирование, переименование с проверкой `revision`,
  удаление. Название и описание хранятся и в колонках, и внутри определения.
  Сохранение целого определения добавится в `updateLessonTemplate` на шаге 2.
- `lib/lesson-templates/system-templates.js`: системные шаблоны как данные,
  у шаблона 1 `definition: null`.
- `createGenerationPlan`, `createGenerationSkeleton` принимают JSON шаблона
  (`null` — шаблон 1 на старых секциях) и компилируют его сами.
- Черновик при создании сохраняет снимок определения (у шаблона 1 — `NULL`).
  Повтор генерации берёт `findLessonDraftTemplate`: снимок, а у старых
  черновиков — системный файл. В ответе черновика есть `templateTitle`.
- Правила редактирования Grammar Presentation и Guided Communication больше не
  проверяют `template === 'template-2'`: они привязаны к компонентам. Число
  карточек Guided Communication нельзя менять относительно сгенерированного.
- API (только админ): `GET /api/lesson-templates` → `{ templates }`;
  `POST /api/lesson-templates/:id/copy` `{ title? }` → 201 `{ template }`;
  `PATCH /api/lesson-templates/:id` `{ revision, title?, description? }` →
  `{ template }`, 409 при устаревшей версии; `DELETE` → `{ ok: true }`.
  Системные шаблоны менять и удалять нельзя (403), шаблон 1 копировать
  нельзя (409).
- Имя схемы ответа у копий содержало UUID (`easyclass_<uuid>_warm_up`); с 0c-2
  оно `easyclass_<этап>` у всех шаблонов.

### 1b. Интерфейс ✓

- Страница `/lesson-templates` (`lesson-templates.html`,
  `assets/lesson-templates.{js,css}`), пункт «Шаблоны уроков» в меню админа
  после «Черновиков». Системные шаблоны сверху, затем копии. «Копировать»
  сразу открывает копию на переименование; «Изменить» правит название и
  описание; «Удалить» предупреждает, что черновики останутся.
- «Новый урок» загружает список шаблонов при каждом открытии окна (копии

  общие: у копий шага 1 те же `inputs`, что у шаблона 2. Построение полей из
  `inputs` перенесено в шаг 2: оно нужно, когда редактор научится их менять.
- Карточка черновика показывает `templateTitle` — название из снимка.
- Проверено в браузере на копии базы: копирование, переименование,
  синтетический урок по копии (все 8 этапов из `example()`), удаление копии с
  живым черновиком, ширина телефона.

## 4. Шаг 2: редактор

По разделу 10 спецификации: урок как есть, связи плашками, панель блока с
параметрами в пределах контрола, указания с «Вернуть по умолчанию», статус
«Связи в порядке / N проблем». Системные шаблоны — только чтение с «Сделать
копию». Сюда же — поля ввода «Нового урока» из `inputs` шаблона (перенесено из
шага 1).

Что выяснилось в коде:

- `example()` и `build` контролов есть только на сервере, поэтому урок на
  примерах и ошибки проверки редактор получает с сервера одним запросом.
- `lesson-view.js` рисует компоненты через `componentRenderers`, но обвязка
  `LessonView.create` привязана к DOM страницы урока. Нужно вынести
  `renderComponent(component, options)`. Редакторы статичных компонентов из
  `lesson-editor.js` уже отдают `onSave(changes, id)`.
- Поля «Нового урока» зашиты: сервер ждёт `topic`, `warmUpTopic`,
  `grammarTopic`, черновик хранит их в отдельных колонках.
- `updateLessonTemplate` меняет только название и описание; проверка
  определения и `revision` уже есть.

### Решения

1. **Сохранение явное:** кнопка «Сохранить» и признак несохранённых изменений,
   как в редакторе урока. Сломанный шаблон сохранить нельзя.
2. **«Вернуть по умолчанию»** возвращает указания того же блока в исходном
   системном шаблоне, а не `control.defaultInstructions`: в шаблонах 1 и 2
   переопределены 69 из 85 указаний.
3. **`topic` обязателен** в каждом шаблоне: из него название урока и обложка.
   В редакторе его не удалить.
4. **«Пробный урок» пока не делаем.** Проверка качества — обычный «Новый урок»
   по сохранённой копии.
5. **Ряд (`row`)** — одна рамка; части ряда выбираются в панели,
   перетаскивать их внутри ряда нельзя.

### Подшаги

- **2a. Сервер. ✓**
  - У параметров контролов есть подписи и вид (`integer`, `choice`, `flag`,
    `text`, `textList`, `custom`); пары «от — до» связаны через `atMost`.
    Ошибка параметра несёт `param`, чтобы панель блока подсветила поле.
  - Ключи оформления описаны в `lesson-templates/chrome-fields.js`. Значения
    оформления пока не проверяются — это 2d.
  - Миграция 022: `lesson_templates.system_template_id` — системный шаблон,
    от которого идёт копия, в том числе через копии копий.
  - `GET /api/lesson-templates/:id` — сводка и определение.
  - `PATCH /api/lesson-templates/:id` принимает `{ revision, definition }`;
    сломанный шаблон — 400 с `errors`.
  - `POST /api/lesson-templates/preview` получает
    `{ definition, systemTemplateId }` и отдаёт `{ errors, lesson, blocks }`.
