# Синхронизация Grammar Presentation

Стадия `grammar-presentation` доступна в классе. Text Panel и Quick Rule
используют существующий рендеринг и политику видимости Markdown Card.
Teacher Note и Answer Key с политикой teacherOnly не передаются ученику.

Drag Words in Text использует один компонент для черновика, ученика и учителя.
Правила находятся в ExerciseState.apply и вызываются локально и на сервере.
Авторский JSON и редактор сохраняют прежний формат; ключи в тексте [[answer]]
доступны клиенту для немедленной проверки, но не выводятся в пустые пропуски,
DOM-атрибуты ответов или accessibility-подписи. Проверка больше не зависит от DOM.

Действия select-word (itemId — слово либо null) и place-word (itemId —
gap-1, gap-2 и т. д., value — слово, attemptId — ID попытки) разрешены ученику.
Учитель видит выбранное слово, правильные размещения и подсветку ошибочной попытки.
Координаты указателя и плавающая карточка остаются локальными.
Правильный ответ блокирует пропуск и убирает слово из банка; неверный можно исправить.

Состояние exercises[componentId] содержит selectedId, placed и последнюю attempt.
ID попытки предотвращает повтор подсветки при подтверждении сервера; snapshot
восстанавливает результат без анимации. updateState не отправляет события
и сохраняет узлы пропусков и банка. Отключение и dispose освобождают drag ghost.
CSS компонентов не изменён.

Dropdown Choice теперь также проверяет ответ до отправки события во всех стадиях.
Его presentation содержит answerKey для общей локальной проверки и наложения
очереди. Ключ не отображается в меню ученика. Учитель сохраняет возможность
открывать меню без изменения общего ответа.

Существующая очередь и expectedVersion обеспечивают серверное подтверждение.
Сервер самостоятельно проверяет права, стадию, варианты и блокировку ответов.
Ответы сохраняются в состоянии класса, отдельно от урока, без SQL-миграции.
Неподтверждённые действия откатываются при ошибке или обрыве связи.

Автоматические проверки: общие правила, локальная реакция до события,
права, сохранение DOM, pointer drop, отключение, дедупликация подсветки,
наложение очереди, откат, WebSocket-синхронизация и восстановление после
перезапуска сервера. Браузерную проверку выполняет пользователь.
