## Подготовленные изменения

Для каналов урока и заметок добавлен журнал `[class-connection]`:
открытие/принятие соединения, замена вкладки, отказ занятого места, код закрытия,
heartbeat timeout, время последнего pong, идентификатор страницы и соединения.
Браузер передаёт видимость страницы, pagehide/pageshow, online/offline,
тип навигации и код предыдущего закрытия при переподключении.

Данные клиента — диагностические подсказки, не доверенные факты о причине сбоя.
При полном обрыве событие ухода может не дойти. Отсутствие события не доказывает
отсутствие ухода. Количество клиентских записей ограничено 24 в минуту на соединение;
последнее допустимое событие сохраняется в записи закрытия даже при исчерпании лимита.
Идентификатор участника — HMAC с ключом, существующим только в памяти процесса.
Cookies, токены, ответы и содержимое заметок не журналируются.

Интеграционные тесты для обоих каналов проверяют отказ второму ученику,
замену вкладки, принудительный сетевой обрыв, восстановление и последующую
работу с состоянием/синхронизацией. Диагностика не меняет правила допуска участников.
Изменения подготовлены локально; исторические события они восстановить не могут.

Следующий продуктовый вопрос: просмотр учителем своего урока по ученической ссылке
может занимать единственное место. Для предотвращения этого нужен отдельный режим
предпросмотра или явное освобождение места, с сохранением защиты от второго гостя.

Проверка: `npm run check` прошла, 537 тестов. Дополнительно полный набор прошёл
на отдельной копии HEAD с изменениями только этой диагностики. В неё не включались
параллельные изменения шаблонов в общей рабочей папке. Клиент ждёт явного
подтверждения поддержки диагностики сервером, поэтому после отката сервера
не отправляет неизвестные старому протоколу сообщения.
