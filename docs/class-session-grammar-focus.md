# Синхронизация Grammar Focus

Стадия `grammar-focus` доступна в классе. Dropdown Choice использует уже
существующую синхронизацию. Gap Fill и Mini Situation используют одни и те же
компоненты в черновике, у ученика и учителя; оформление и CSS не изменены.

## Состояние и действия

Оба компонента поддерживают `presentation`, `exerciseState`, `interactive`,
`onAction`, `updateState` и `setInteractive`. Правила в `ExerciseState.apply`
вызываются локально до отправки события и независимо на сервере. В классе
вводит ученик; учитель наблюдает через поля readOnly.

Действие `type-answer` содержит `componentId`, `itemId` и `value` (до 1000
символов). Для Gap Fill itemId — авторский ID пропуска, для Mini Situation —
`sentence-1` … `sentence-N`. Порядок и число предложений фиксированы в уроке
класса. Сервер проверяет роль, активную стадию, версию, поле, тип и длину текста.

Ответы находятся в `exercises[componentId].answers[itemId]`. Gap Fill хранит
`value` и `status` (`correct` или `pending`), Mini Situation — только `value`.
Состояние сохраняется в существующем `class_live_state`, отдельно от авторского
JSON, без миграции БД. В черновике пробные ответы остаются локальными.

Gap Fill сохраняет прежнюю проверку регистра, пробелов и апострофов, зелёную
галочку и возможность менять правильный ответ. Ошибочная попытка не получает
красной подсветки. Ключи передаются в данных для локальной проверки, но не
добавляются в отображаемый текст, data-атрибуты или accessibility-подписи.
Авторские подсказки example сохраняются. Mini Situation не оценивается
автоматически и сохраняет бейдж Manual check.

Обновления состояния не пересоздают поля и не присваивают input.value, если
текст уже совпадает. Подтверждения сервера накладываются на оставшиеся действия
в существующей очереди, поэтому более свежий ввод не заменяется старым.
Каждое изменение отправляется последовательно, без объединения событий.
При обрыве связи неподтверждённые изменения откатываются, ввод блокируется до
подключения; snapshot восстанавливает сохранённые ответы.

## Вложенные карточки

Поиск действий на клиенте и сервере использует существующий ComponentTree.
Card Row передаёт каждой Markdown Card её настройки сессии и обновления
видимости через адаптер. Сервер фильтрует карточки индивидуально:
`always`, `controlled`, `teacherOnly` сохраняют прежний смысл. Teacher Note
и Answer Key с политикой teacherOnly не передаются ученику.

Авторский Card Row по-прежнему требует 2–3 карточки. Его presentation допускает
0–3 карточки после фильтрации. Пустой ряд не отображается. Отдельного рендерера
для ученика нет; используется прежняя сетка и оформление.

## Проверки

`npm run check`: правила, локальный результат до события, ограничения сервера,
сохранение DOM и отсутствие лишних присваиваний value, очередь быстрого ввода,
откат, фильтрация вложенных карточек, WebSocket и восстановление после
перезапуска сервера.

Браузерную проверку выполняет пользователь:

- Открыть Grammar Focus у учителя и ученика; сравнить оформление с черновиком.
- В Gap Fill набрать правильный ответ и затем изменить его; проверить галочку
  и текст у обоих участников, положение курсора при быстром вводе.
- В Mini Situation заполнить несколько строк; проверить отображение у учителя
  и восстановление после перехода между стадиями и обновления страницы.
- Для ряда с controlled-карточкой проверить её показ и скрытие учителем.
- При разрыве связи проверить откат неподтверждённого ввода и восстановление
  серверного состояния после подключения.

## Sentence Correction (шаблон 2)

Task 3 использует общий компонент `sentenceCorrection` в черновике и классе.
Действие `type-answer` адресует авторский `itemId`, значение ограничено 1000
символами. В классе ввод разрешён только ученику; преподаватель наблюдает через
readOnly-поля. Это ограничение проверяется и адаптером, и сервером.

Ответ сохраняется в `exercises[componentId].answers[itemId]` как `{ value,
status }`, где status — `correct` или `pending`. Клиент и сервер используют
одинаковую проверку по массиву допустимых ответов. Подтверждения и обновления
не пересоздают поля и не присваивают value при совпадающем тексте. Используется
существующая очередь событий, откат при отключении, восстановление snapshot
и сброс стадии. Миграция БД не нужна.

Карточка Answer key не передаётся ученику. Как у Gap Fill, допустимые ответы
самого упражнения присутствуют в presentation для локальной проверки, но
не выводятся в DOM или accessibility-подписях как подсказки.

`test/sentence-correction*.test.js` проверяет сравнение ответов, редактор,
наблюдение, очередь, сохранение при повторном открытии БД, смену и сброс стадии.
`test/server-template-two.test.js` проверяет API и атомарное обновление ключа.

## Sentence Matching (шаблон 2, Task 4)

`sentenceMatching` содержит 2–12 пар `{ id, left, right }`. Левые половинки
сохраняют авторский порядок; правая колонка перемешивается один раз через
`_layouts`. Номера относятся к началам, буквы — к окончаниям и не меняются
после перестановки. Отдельной карточки Answer key нет.

В классе выбирать начало (`select-word`) и собирать пару (`match-word`) могут
учитель и ученик. Состояние `{ selectedId, matches, rightOrder, attempt }`
сохраняется в `exercises[componentId]`. Сервер проверяет доступность половинок,
правильность, роль, активную стадию и версию. Ошибка сохраняет выбранное начало;
верная пара фиксируется на строке начала. Свободные окончания сохраняют
относительный порядок, уже собранные пары не переставляются. Отключение,
очередь подтверждений, восстановление и reset используют общий механизм класса.

Подсказка вычисляется по `viewerRole === 'teacher'`: верное окончание выбранного
начала слегка затемняется только у учителя. Ключ остаётся в presentation для
локальной проверки, как у Match Words; это визуальная подсказка, а не защита
ответов от просмотра данных клиентом. Собранные пары у обоих участников имеют
мягкий зелёный фон и галочки.

Один рендерер используется в черновике и классе. CSS Grid выравнивает половинки
по строкам даже при переносе текста. FLIP через Web Animations API выполняет
перестановку за 480 мс с `cubic-bezier(0.2, 0, 0, 1)`. Прерывание измеряет текущее
видимое положение; подтверждение без изменения порядка не повторяет движение.
Snapshot и `prefers-reduced-motion` отображаются без анимации. Кнопки поддерживают
клавиатуру, Escape снимает выбор, статус сообщает прогресс.

Редактор позволяет менять заголовок, инструкцию и тексты правильных пар.
`PATCH /api/lesson-drafts/:id/sentence-matching/:componentId` доступен владельцу
черновика на проверке, сохраняет число и ID пар; после правки пробные ответы
сбрасываются. Task 4 добавляется при создании шаблона 2; существующие сохранённые
уроки автоматически не изменяются.

Проверки: `sentence-matching.test.js` (включая все 720 порядков решения,
подсказки, редактор, анимацию, очередь и reset), `sentence-matching-session.test.js`
(сохранение в БД и восстановление), `server-template-two.test.js` (API редактирования).
